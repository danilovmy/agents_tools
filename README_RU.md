## Xiaomi OCR: локальный запуск

Скрипт `tests/codex/ocr.py` распознаёт изображение локально: запускает модель через `llama-mtmd-cli`, выводит текст и статистику, затем завершает процесс. Сервер не требуется.

Для запуска нужны Python 3, `llama-mtmd-cli` в `PATH` и два файла модели:

- `D:\Downloads\Xiaomi-OCR-0.Q4_K_M.gguf`
- `D:\Downloads\Xiaomi-OCR-0.mmproj-bf16.gguf` — [визуальный модуль](https://huggingface.co/prithivMLmods/Xiaomi-OCR-0-GGUF/resolve/main/Xiaomi-OCR-0.mmproj-bf16.gguf)

Пути к файлам модели заданы в начале скрипта. Запуск примера из корня проекта в PowerShell:

```powershell
python tests\codex\ocr.py tests\codex\photo_2026-10-31_14-46-10.jpg
```

Вместо фотографии из примера можно указать путь к другому изображению. Скрипт показывает общее время, приблизительное время инициализации модели и время распознавания. Для оценки качества можно передать файл с правильной расшифровкой в UTF-8:

```powershell
python tests\codex\ocr.py tests\codex\photo_2026-10-31_14-46-10.jpg --reference путь\к\etalon.txt
```

При наличии эталона скрипт выводит проценты ошибок по символам (CER) и словам (WER). Без эталонного текста качество определить нельзя.

## Настройка скилла Xiaomi OCR

Скилл `skills/ocr-reader-xiaomi` использует Transformers и PyTorch и не зависит от тестового скрипта выше. Нужны Python 3.12, зависимости из `requirements.txt` и исходная модель Xiaomi-OCR-0 в формате Safetensors; `llama.cpp` не требуется.

Создайте окружение и установите зависимости из корня проекта:

```powershell
python -m venv skills\ocr-reader-xiaomi\.venv
& skills\ocr-reader-xiaomi\.venv\Scripts\python.exe -m pip install -r skills\ocr-reader-xiaomi\requirements.txt
if (-not (Test-Path skills\ocr-reader-xiaomi\.env)) { Copy-Item skills\ocr-reader-xiaomi\.env.example skills\ocr-reader-xiaomi\.env }
```

В `skills/ocr-reader-xiaomi/.env` задайте `XIAOMI_OCR_MODEL_PATH`: абсолютный путь к локальной папке модели, путь от папки скилла с префиксом `./`, например `./.cache/model`, или ID модели на Hugging Face, например `xiaomi-research/Xiaomi-OCR-0`. С ID модель будет загружена при первом запуске. Переменные окружения имеют приоритет над `.env`; локальный `.env` не сохраняется в Git.

Основная интеграция рассчитана на Windows и уведомления OpenClaw. Для других агентов и операционных систем используйте `-s`, чтобы отключить уведомления; потребуются совместимые зависимости Python. См. [инструкцию скилла](skills/ocr-reader-xiaomi/SKILL_RU.md) и [проверку после установки](skills/ocr-reader-xiaomi/test/README.md). Выбранная модель не готова для надёжного распознавания русских текстов; сверяйте результат с оригиналом.

По умолчанию одноимённое изображение в архиве заменяется; `-p` / `--protected` запрещает замену изображения и вызывает ошибку при совпадении. Перед OCR, после переноса при его наличии, старый `.txt` удаляется независимо от флага, а результат записывается напрямую. При ошибке распознавания до записи `.txt` отсутствует; ошибка во время записи может оставить неполный файл. Архив скилла находится в `skills/ocr-reader-xiaomi/data/archive`: для него необходимы разрешения на просмотр и запись, а для перемещения файла — право удаления в исходной папке.

Расшифровка сохраняется в текстовый файл. Флаг `--stdout` дополнительно выводит её в stdout. Сообщения скилла записываются в `logger.log`, ошибки также выводятся в stderr. Вывод Python направляется в stderr, однако нативные библиотеки могут писать непосредственно в stdout.

## Настройка скилла OCR

Скилл `skills/ocr-reader` использует docTR для распознавания и docuwarp для выпрямления изображения. Нужен Python 3.11 или новее. Из корня проекта установите зависимости:

```powershell
python -m venv skills\ocr-reader\.venv
& skills\ocr-reader\.venv\Scripts\python.exe -m pip install -r skills\ocr-reader\requirements.txt
```

По умолчанию кэш docTR находится внутри скилла, в `skills/ocr-reader/.cache/doctr`; веса сохраняются в его подпапке `models` и при отсутствии загружаются библиотекой при первом использовании. Чтобы изменить путь, задайте `DOCTR_CACHE_DIR` в `skills/ocr-reader/.env` или в окружении процесса: укажите абсолютный путь либо относительный путь от папки `skills/ocr-reader`, например `.cache/doctr`. Переменные окружения имеют приоритет над `.env`; локальный `.env` не сохраняется в Git. Подстановка переменных вида `${MODELS_DIR}` в путях не поддерживается.

В `.env` пути Windows с обратными косыми чертами записывайте без кавычек или в одинарных кавычках, например `DOCTR_CACHE_DIR='D:\Models\doctr'`: в двойных кавычках `python-dotenv` обрабатывает последовательности вроде `\t` как специальные символы.

Docuwarp по умолчанию использует свои модели из установленного пакета. Необязательная переменная `OCR_UNWARP_MODEL_PATH` в `.env` или окружении позволяет указать абсолютный путь к другому файлу `uvdoc.onnx`; вспомогательная модель остаётся в пакете.

Модель распознавания, используемая по умолчанию в docTR 1.1.0, не готова для работы с русскими текстами: в её наборе символов нет кириллицы. Поддержка языков зависит от выбранной модели и версии docTR.

Одноимённое изображение в `skills/ocr-reader/data/archive` по умолчанию заменяется; `-p` / `--protected` запрещает эту замену. Перед OCR, после перемещения при его наличии, старый `.txt` удаляется независимо от флага, а результат записывается напрямую. При ошибке распознавания до записи `.txt` отсутствует; ошибка во время записи может оставить неполный файл. Для архива нужны разрешения на просмотр и запись, для перемещения исходника — право удаления в исходной папке.

Основная интеграция рассчитана на Windows и OpenClaw. С флагом `-s` уведомления OpenClaw отключаются, и скрипт можно использовать на других системах при наличии совместимых зависимостей. Реальный запуск OCR проверен на Windows; другие ОС пока не проверялись. Инструкция по проверке после установки находится в [skills/ocr-reader/test/README.md](skills/ocr-reader/test/README.md).

OCR-скиллы пока не проверялись на Linux и macOS.
