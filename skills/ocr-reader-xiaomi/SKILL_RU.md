# Xiaomi OCR: инструкция на русском

[English](SKILL.md)

Скилл распознаёт изображения и многостраничные PDF локальной моделью Xiaomi-OCR-0 через Transformers и PyTorch. Основная интеграция рассчитана на Windows и уведомления OpenClaw. Другие агенты и операционные системы могут использовать `-s`, отключающий уведомления OpenClaw, при наличии совместимых зависимостей. Выбранная модель не готова для надёжного распознавания русских текстов; сверяйте результат с оригиналом.

## Установка

В папке установленного скилла создайте виртуальное окружение Python 3.12, установите зависимости и создайте `.env` из примера, если его ещё нет. Windows PowerShell:

```powershell
python -m venv .venv
& .\.venv\Scripts\python.exe -m pip install -r requirements.txt
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
```

Linux или macOS при наличии совместимых зависимостей:

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
[ -f .env ] || cp .env.example .env
```

Запускайте `ocr.py` через Python этого окружения. В `.env` задайте `XIAOMI_OCR_MODEL_PATH`: ID модели на Hugging Face, абсолютный путь к локальной папке модели или путь от папки скилла с префиксом `./`, например `./.cache/model`. Нужна исходная модель Xiaomi-OCR-0 в формате Safetensors; GGUF не поддерживается. По ID веса могут быть загружены при первом запуске. Переменные окружения имеют приоритет над `.env`. Проверка после установки описана в [test/README.md](test/README.md).

## Запуск

Используйте абсолютные пути к интерпретатору, `ocr.py` и входному файлу. Для Windows и OpenClaw укажите агента и сессию:

```text
<skill-dir>/.venv/Scripts/python.exe <skill-dir>/ocr.py -a <agent> -sid <session_id> <absolute-input-path>
```

Для других агентов и автономного запуска укажите `-s`, чтобы отключить уведомления. Флаг `-stdout` или `--stdout` выводит расшифровку:

```text
<venv-python> <skill-dir>/ocr.py -s --stdout <absolute-input-path>
```

Флаги указывайте перед списком входных файлов. В обычном режиме не используйте `-k`; он оставляет исходник и расшифровку на месте для отладки. Файл перемещается в `data/archive` в папке скилла. Одноимённый входной файл заменяется по умолчанию; `-p` / `--protected` запрещает заменять другой архивный входной файл. После подготовки входного файла одноимённый старый `.txt` удаляется независимо от `-p`, а результат записывается напрямую. При ошибке до записи расшифровка отсутствует; ошибка во время записи может оставить неполный файл.

Изображение передаётся без выпрямления; PDF рендерится и обрабатывается постранично. Если результат содержит `Xiaomi OCR returned unknown response`, сообщите, что изображение не распознано. Без `-s` скрипт асинхронно отправляет уведомления OpenClaw `[ocr-start]` и `[ocr-done]` через `openclaw.cmd`. Флаг `-v` добавляет подробности в `logger.log`; ошибки также выводятся в stderr. Вывод Python перенаправляется в stderr, однако нативные библиотеки могут писать непосредственно в stdout. Папка скилла должна быть доступна для записи журнала, архива и локального кэша.
